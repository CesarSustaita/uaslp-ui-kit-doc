El componente **File Uploader** `ui-file-uploader` es el campo estándar para la recolección y gestión de archivos cargados por el usuario desde su dispositivo. Este componente centraliza toda la experiencia de interacción para la carga de documentos: zonas de arrastre **(drag and drop)**, exploración de archivos, limitación de formatos, validación de tamaños y visualización de estados de alerta o error.
Proporcionar una experiencia de entrada de datos pre-estilizada y validada que se adapta a las reglas de tu sistema.

## ¿Cuándo debería usarse?
Usa este componente cuando quieras:

- **Permitir la carga de documentos:** Facilitar la recepción de archivos locales (como identificaciones, comprobantes, imágenes o reportes) mediante selección directa o arrastrando el archivo a la interfaz.
- **Controlar restricciones técnicas en el cliente:** Validar automáticamente el peso máximo en megabytes (maxSize) o formatos específicos (accept) antes de que el archivo sature o viaje innecesariamente hacia el servidor.
- **Gestionar cargas individuales o múltiples:** Resolver flujos que requieran un único archivo de soporte o permitir la selección masiva de elementos según lo dicte el formulario.

## Manejo y subida de archivos
El componente `<ui-file-uploader>` no realiza subidas automáticas ni conexiones directas con ningún servidor o API de backend por sí solo. Su función principal es actuar como una capa intermedia de validación, filtrado y preparación de archivos en el lado del cliente (frontend).

### Flujo de preparación del archivo
Cuando un usuario interactúa con el componente, ya sea arrastrando archivos a la zona de caída (Drag and Drop) o utilizando el explorador nativo del dispositivo (Examinar), el componente ejecuta el siguiente flujo lógico:

- **1. Intercepción y Validación:** El componente captura el archivo localmente y evalúa de inmediato si cumple con las restricciones técnicas que definiste (formatos permitidos en accept y peso máximo en maxSize).

- **2. Filtrado Excluyente:** Si el archivo es válido, se añade automáticamente a una lista interna de preparación.
<Aside  title="Si el archivo falla alguna regla">
Es rechazado de inmediato, el componente no lo almacena y activa visualmente el estado correspondiente **(warning o negative)** para notificar al usuario el motivo del rechazo.
</Aside>

- **3. Acoplamiento en Lista de Espera:** Los archivos aprobados se guardan en un arreglo temporal dentro del componente. Si la propiedad multiple está inactiva, cada archivo nuevo que sea válido reemplazará al anterior; si está activa, se irán acumulando en una lista interactiva donde el usuario final puede previsualizarlos o eliminarlos individualmente antes de confirmar.

- **4. Cohesión con el Formulario:** Esta lista de archivos válidos permanece "en espera" y perfectamente integrada con el estado del resto de tus campos (como campos de texto, selectores, etc.), permitiendo que toda la información del formulario se mantenga unificada.

- **5. Listo para el Procesamiento (Backend):** Una vez que el usuario decide enviar el formulario completo, el desarrollador tiene dos formas de obtener la lista de archivos limpios y validados para procesarlos: ya sea escuchando en tiempo real el evento personalizado `ui-files-changed` mediante un listener, o accediendo directamente a la propiedad `.files` del componente. Con cualquiera de estos dos métodos, se pueden empaquetar los archivos (por ejemplo, en un objeto **FormData**) y realizar de forma segura la petición de subida hacia los servicios de su Backend.

## Disparador de Eventos
El componente `<ui-file-uploader>` es un proxy para los eventos del campo de carga de archivos nativo. Re-emite un evento clave para la gestión de datos como un Evento Personalizado (CustomEvent):

- `ui-files-changed`: Se dispara en tiempo real cada vez que la lista de archivos válidos seleccionados cambia (ya sea porque el usuario arrastró nuevos archivos, usó el explorador, o eliminó un archivo de la lista interactiva). Es el evento ideal para el binding instantáneo y el manejo del estado del formulario.

### Estructura de `detail`
Este evento emite un objeto detail que mantiene la consistencia técnica del sistema de diseño:

| Propiedad | Tipo          | Descripción                                                                              |
|-----------|---------------|--------------------------------------------------------------------------------------------|
| `files`   | <span style={{whiteSpace: "nowrap"}}>`Array<File>` </span> | Un arreglo con los objetos nativos de tipo File que ya pasaron las validaciones de formato y tamaño, listos para procesar.                   |
| `id`      | <span style={{whiteSpace: "nowrap"}}>`string` </span>     | El ID único del File Uploader. Obligatorio para la trazabilidad, el debugging y la gestión del formulario.

<Aside type="caution" title='Importante'> Por lo tanto, es una **práctica obligatoria** asignar manualmente el atributo `id` a todas las instancias de los inputs para saber identificarlos</Aside>

## Obtención de archivos y eventos
Para escuchar los eventos emitidos por los componentes de este UI Kit, la opción más confiable es usar **`addEventListener`**, ya que garantiza que los eventos personalizados se reciban **correctamente**.

Para recuperar y procesar los archivos validados para este componente se tiene dos enfoques válidos según la arquitectura de tu aplicación: mediante la escucha del evento personalizado **`ui-files-changed`** o consultando directamente la propiedad **`.files`** mediante la referencia del elemento en JavaScript.

En **frameworks** _(Vue.js, React, Angular)_ también puede usarse **`addEventListener`**, aunque cada uno ofrece su propia forma de manejar eventos, que igualmente es válida y en la mayoría de los casos funcionan sin problema. Sin embargo, cada framework tiene particularidades importantes que tu como desarrollador debes considerar:

- **Vue**: Normalmente funciona de forma nativa, ya que Vue respeta los **eventos del DOM** tal como se emiten.
- **Angular**: Suele funcionar, en algunas versiones antiguas del framework tenían **limitaciones** con eventos provenientes de Web Components.
- **React**: Puede detectar eventos personalizados pero no siempre. Su sistema interno de `Synthetic Events` no garantiza la **compatibilidad al 100%**, por lo que el comportamiento puede variar entre navegadores y versiones.
